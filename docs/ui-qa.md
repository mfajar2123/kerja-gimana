# UI quality review

## Scope

The review covers local Nuxt development mode and the generated Node production server with Supabase credentials absent. The homepage is checked at widths 320, 375, 390, 440, 768, 1024, 1440, and 1728px, including shorter desktop viewports. Public routes are inspected at 320, 768, and 1440px. Screenshots and browser diagnostics are generated by `node scripts/visual-review.mjs` under the ignored `artifacts/ui-qa/` directory.

Private layouts and company detail tabs use explicitly fictional browser-only API fixtures in `tests/e2e/fixture-ui.spec.ts`. No fixtures are inserted into a database or returned by application APIs. These checks validate rendering and navigation, not actual authentication, database permissions, or writes.

## Findings and corrections

| Finding | Correction |
| --- | --- |
| The absolute-positioned "CARI TAHU DULU" caption overlapped the hero actions and scroll indicator at desktop widths. | Move caption and scroll link into a separate normal-flow footer row with independent spacing. Allow content to increase hero height on short viewports. |
| Directory, comparison, authentication, contribution, and company pages referenced CSS classes without corresponding style rules. | Add consistent page layouts, readable headings, visible field borders, focus treatment, tables, tabs, and responsive spacing using the existing semantic tokens. |
| Native form validation was disabled, allowing missing fields and the required contribution declaration to reach submission handlers. | Restore native required, email, length, and checkbox validation. Server validation remains authoritative. |
| Escape did not return mobile-navigation focus to its trigger. | Restore focus to the menu button on Escape. |
| Search keyboard selection could move beyond the five visible suggestions; Escape did not work with no matches. | Limit the data used for rendering and keyboard selection together; expose the active option to assistive technology; dismiss on Escape and focus leaving the search. |
| Client-side navigation could open private pages while document requests redirected to sign-in. | Add a client route guard backed by the existing authenticated API; retain the original path and query when redirecting. Server-side authorization remains in place. |
| Admin child routes rendered only the parent overview because the parent had no NuxtPage outlet. | Add the child outlet, admin section navigation, and a role-gated dashboard entry. |
| Error pages used the framework default appearance. | Add an Indonesian error layout and a native link back home that works before hydration and without JavaScript. |
| The directory repeated the same empty message twice. | Present one status message in the empty state. |
| The industry endpoint returned an avoidable 503 during backend-free UI previews. | Return an empty taxonomy when Supabase is unconfigured. |
| Small self-hosted font subsets were inlined as data URLs by the production bundler, then blocked by the font CSP. | Allow data URLs only in the font directive alongside same-origin fonts; retain the other CSP restrictions and check browser console errors in the homepage regression test. |
| The assembly text's initial animation opacity reduced red and muted text below the large-text contrast threshold against maroon. The production accessibility audit exposed this after motion initialized. | Keep assembly text fully opaque throughout the transform animation and wait for initialization before running the accessibility audit. |
| At 320×900px the last FAQ could remain transparent inside the visible viewport because the reveal observer excluded the bottom 7% of the screen. | Observe the entire viewport and add the exact viewport to the scroll-reveal regression test. |

## Validation

Playwright checks hero geometry, stylesheet application, usable field dimensions, responsive overflow, mobile navigation, scroll reveals, FAQ keyboard interaction, invalid form submission, anonymous redirects, error recovery, private fixture layouts, and company tab empty states. Axe checks for serious and critical WCAG findings on the audited pages. Typecheck, ESLint, and existing unit tests are run separately.

This is not a full WCAG certification, real-device audit, or production performance measurement. Live Supabase Auth, SMTP, database RLS, and submission/moderation integration still require a connected Supabase test project.
